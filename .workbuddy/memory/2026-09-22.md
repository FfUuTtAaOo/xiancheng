## 修复 CMake 配置失败（工程改名 Y75_Model → xiancheng）

**现象**：VS Code 预设 Debug 配置报错
- `The current CMakeCache.txt directory ... is different than the directory d:/ST/workspace/vscode/Y75_Model/build/Debug where CMakeCache.txt was created`
- `The source ".../xiancheng/CMakeLists.txt" does not match the source ".../Y75_Model/CMakeLists.txt" used to generate cache`

**根因**：工程目录从 `D:/ST/workspace/vscode/Y75_Model` 复制/改名为 `xiancheng` 时，旧的 `build/Debug/` 被一并带过来。缓存里 `CMAKE_HOME_DIRECTORY` 仍指向老路径。

**修复**：删除 `D:/ST/workspace/vscode/xiancheng/build/Debug/`（纯生成物，可重建），重新配置即可。
- 缓存中的路径已确认修正为 `CMAKE_HOME_DIRECTORY:INTERNAL=D:/ST/workspace/vscode/xiancheng`，`CMAKE_PROJECT_NAME:STATIC=xiancheng`
- 完整编译通过，产出 `xiancheng.elf` / `xiancheng.hex` / `xiancheng.bin` / `xiancheng.map`
- 资源占用：RAM 7744 B / 20 KB (37.81%)，FLASH 43728 B / 128 KB (33.36%)

**遗留（非阻塞）**：
- `Y75_Model.ioc` 内仍为 `ProjectManager.ProjectName=Y75_Model`，改名后若用 CubeMX 重新生成代码会带出旧工程名。可选清理。
- `Core/Src/self_test.c` 有 2 个 `-Wunused-function` 警告：`is_all_zeros`、`has_valid_float` 定义未使用。

## 可复用的命令行构建方式

STM32 VS Code 扩展的 `cube-cmake` 依赖 `cube` 命令与 CUBE_BUNDLE_PATH，脱离 VS Code 直接调用需补齐环境：

```bash
BUNDLE="/c/Users/y3010/AppData/Local/stm32cube/bundles"
CORE="/c/Users/y3010/.vscode/extensions/stmicroelectronics.stm32cube-ide-core-1.4.0-win32-x64/resources/binaries/win32/x86_64"
BCMAKE="/c/Users/y3010/.vscode/extensions/stmicroelectronics.stm32cube-ide-build-cmake-1.46.0-win32-x64/resources/cube-cmake/win32/x86_64"
export PATH="$CORE:$BCMAKE:$BUNDLE/gnu-tools-for-stm32/14.3.1+st.2/bin:$BUNDLE/ninja/1.13.2+st.1/bin:$PATH"
export CUBE_BUNDLE_PATH="C:/Users/y3010/AppData/Local/stm32cube/bundles"

"$BCMAKE/cube-cmake.exe" -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_TOOLCHAIN_FILE=D:/ST/workspace/vscode/xiancheng/cmake/gcc-arm-none-eabi.cmake \
  -DCMAKE_COMMAND=cube-cmake -DCMAKE_EXPORT_COMPILE_COMMANDS:BOOL=TRUE \
  -S D:/ST/workspace/vscode/xiancheng -B D:/ST/workspace/vscode/xiancheng/build/Debug -G Ninja

"$BCMAKE/cube-cmake.exe" --build D:/ST/workspace/vscode/xiancheng/build/Debug
```
